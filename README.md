# 海枢智航 · 霍尔木兹海峡船舶态势分析平台

**融合历史 AIS、新闻事件与智能体问答，让海峡船舶活动可视、可查、可追溯。**

海枢智航面向霍尔木兹海峡的历史海事态势研究，将船舶位置、航行轨迹、新闻报道和统计分析整合到同一地图工作台。用户可以从区域态势出发，查看单船航行过程，比较不同时段的通行与区域活动，并通过自然语言调用分析工具、定位地图和追溯证据。

## 项目价值

海事分析需要同时回答“发生了什么”“船舶如何活动”和“结论依据是什么”。项目围绕这三个问题组织功能：

- **统一查看多源信息**：在地图与时间轴中浏览历史船位和新闻事件，减少在轨迹、报道与统计结果之间反复切换。
- **从态势概览进入具体证据**：由通行数量、区域活动和典型事件逐层查看船舶身份、观测时段、轨迹与报道来源。
- **用自然语言完成分析操作**：智能体调用已有业务工具，将查询结果与地图、分析面板联动，降低使用门槛。

适用于历史航运态势研究、典型事件复盘及海事数据分析教学。

## 核心功能

| 功能 | 主要能力 |
| --- | --- |
| 船舶态势地图 | 浏览历史 AIS 船位，按船名、MMSI 或 IMO 检索船舶；结合地图图层查看航行环境 |
| 轨迹与时间回放 | 按需加载单船分段轨迹，查看实测航速和采样点，沿时间轴回放历史船位 |
| 新闻事件浏览 | 按时间与类型浏览新闻聚合事件，查看中文摘要、关联报道和原文来源 |
| 海峡通行分析 | 基于虚拟双门线识别观测支持的通行，按日期、方向和船型统计，支持两期比较及证据追溯 |
| 区域活动分析 | 使用默认区域或矩形圈选，查询时点在场船舶、时段活动、每日汇总与两期变化，并联动轨迹 |
| 典型案例复盘 | 从四条经审核的新闻入口进入对应船舶轨迹，通过阶段导航、快速回放和证据面板查看航行过程 |
| 智能体问答 | 基于项目知识库和只读业务工具回答问题，支持多轮对话、船舶轨迹定位及通行、区域分析面板联动 |

### 建议体验路径

1. **查看态势**：选择历史日期，浏览船舶分布与新闻时间线，检索并选中一艘船。
2. **追踪航行**：展开轨迹，结合时间轴、分段报位与实测航速观察航行过程。
3. **开展分析**：打开“通行”查看统计和证据，或圈选区域查看在场船舶与时段活动。
4. **复盘事件**：从“典型案例”进入新闻关联船舶，对照航行阶段、AIS 观测与报道原文。
5. **自然语言查询**：打开“智能体”，提出问题并通过回答中的操作入口查看地图或分析结果。

例如，可以询问：

- “统计 2026 年 2 月 25 日至 3 月 3 日每天观测到的油轮通行次数。”
- “比较 2026 年 2 月 25—27 日和 3 月 1—3 日的通行情况。”
- “查询当前圈选区域在 2026 年 3 月 1 日的船舶活动。”

## 技术架构

平台采用前后端分离架构。地图工作台与智能体共同调用后端业务服务，使用一致的查询条件与判定规则；统计结果、轨迹证据和报道来源通过结构化接口返回前端。

| 层次 | 技术与职责 |
| --- | --- |
| 交互展示 | Vue 3、TypeScript、Vite；Leaflet 承载地图与轨迹，ECharts 展示统计图表 |
| 接口与业务服务 | FastAPI、Pydantic、SQLAlchemy；负责参数校验、船位查询、通行判定、区域活动计算与新闻读取 |
| 数据存储 | PostgreSQL / PostGIS；存储船舶、历史报位、来源批次、新闻与聚合事件 |
| 智能体编排 | LangChain `create_agent`；结合项目知识库和只读工具完成查询，返回文字、结构化结果及地图或分析动作 |
| 外部工具接入 | MCP 支持本机 stdio 与 Streamable HTTP，提供固定七个只读业务工具 |

### 实现特点

- **按时间窗口读取海量报位**：地图使用船位快照、窗口预取与按需轨迹加载，避免一次向浏览器传输整批 AIS 数据。
- **分析规则统一**：手动面板与智能体复用通行、区域活动服务，减少不同入口之间的统计口径差异。
- **结论关联证据**：通行结果保留两侧观测记录，区域结果附带观测覆盖信息，案例同时展示轨迹与新闻来源。
- **语言理解与业务计算分工**：模型理解问题并选择工具，统计与规则判定由后端执行；工具调用受参数、次数、时间和结果规模约束。

内部受控 SQL 能力按配置启用，其应用库准备情况见[当前状态](docs/agent_development_plan.md)；外部 MCP 提供只读业务查询。

## 数据基础

项目使用历史 AIS 和已采集的真实新闻报道。AIS 用于描述船舶观测与航行过程，新闻用于提供事件背景与来源，两类数据分别保留证据。

| 数据组成 | 规模与范围 |
| --- | --- |
| 七日 AIS 基础批次 | 4,462 艘船舶、17,921,533 条报位；覆盖 UTC+8 的 2026-02-25 至 2026-03-03 |
| 典型案例补充 | 中海北冰洋 11,640 条报位；MRAIKH、桐林湾与 EGRET 合计 27,255 条报位 |
| 新闻与聚合事件 | 362 篇新闻、82 个聚合事件，支持摘要阅读与来源追溯 |

以上规模来自对应导入批次：七日基础批次于 2026-09-25 对账，案例及新闻增量见 2026-10-25 记录。案例补充具有独立时间范围，不代表同期海峡全船覆盖。详细来源和导入规则见[七日 AIS](docs/real_ais_seven_day_import.md)、[案例轨迹](docs/trajectory_cases.md)与[数据库说明](docs/database_setup.md)。

## 典型案例

平台提供四组人工审核的新闻与轨迹关联，用于展示从报道阅读到航行复盘的完整使用过程。

| 案例船舶 | 展示内容 |
| --- | --- |
| 中海北冰洋 | 结合报道与阶段轨迹，复盘再次尝试后通过海峡的航行过程 |
| MRAIKH（穆赖赫） | 对照 LNG 运输船通行报道与已导入的船舶轨迹 |
| TONG LIN WAN（桐林湾） | 查看新闻关联油轮的历史航迹与原文证据 |
| EGRET | 对照由东向西通行报道、轨迹观测与航行阶段 |

案例面板提供“过程 / 证据”页签、阶段定位和快速回放。缺报区间以灰色虚线示意，并明确标注其并非实测航迹。新闻关联依据预设案例与审核资料，具体标识、来源和关联方法见[典型新闻与轨迹](docs/case_news_entries.md)。

## 本地运行

### 环境准备

准备 Python 3.11+、Node.js/npm、PostgreSQL / PostGIS；Windows 使用 PowerShell 7。以下命令从仓库根目录执行。

仓库不包含恢复当前应用库所需的完整数据包。首次搭建须先阅读[数据库与环境说明](docs/database_setup.md)，准备配套结构与数据；模型问答还需要配置模型服务。

### 安装后端依赖

```powershell
py -m venv .\backend\.venv
.\backend\.venv\Scripts\python.exe -m pip install -r .\backend\requirements.txt
if (-not (Test-Path -LiteralPath .\.env)) { Copy-Item .\.env.example .\.env }
```

在本机 `.env` 中配置数据库连接和模型服务，密码与密钥仅保留在后端环境。

### 启动后端

```powershell
.\backend\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --reload
```

### 启动前端

另开终端执行：

```powershell
cd frontend
npm ci
npm run dev -- --port 5174
```

启动后访问[地图工作台](http://localhost:5174)、[健康检查](http://127.0.0.1:8000/health)或[API 文档](http://127.0.0.1:8000/docs)。前端默认通过 Vite 同源代理访问后端，可选地图资源配置见[本地瓦片服务](deploy/tiles/README.md)。

## 使用范围

当前版本用于本地历史数据分析与演示，尚未正式部署，未接入实时 AIS，也未提供应用内认证授权。完整负载与灾备恢复仍需进一步验证。

统计以已导入的 AIS 观测和项目规则为依据；虚拟门线与分析区域为项目定义。数据缺报、零匹配或时空邻近不能独立证明实际停航、事件因果或海峡整体交通状况。AIS 来源授权、覆盖完整性及第三方资源使用范围仍需核实。
