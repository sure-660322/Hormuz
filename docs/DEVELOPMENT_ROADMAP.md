# 霍尔木兹海峡船舶态势地图开发推进计划

> 版本：2026-08-30 初版  
> 适用范围：`D:\my_project\Hormuz` 当前仓库  
> 数据边界：本文中的船舶、轨迹、事件、告警和分析均为教学模拟，不代表真实 AIS 或真实海上态势。

## 1. 计划目的

本计划的首要目标，是先用现有大规模模拟数据完成一套可操作、可回放、可解释的整体系统，再逐步提高质量并为真实数据、大模型和智能体扩展打基础。

推进原则：

1. 每个阶段都形成一个能在浏览器中看到、操作和验收的结果。
2. 优先复用 Vue、Leaflet、FastAPI、SQLAlchemy、PostgreSQL 和 PostGIS，不提前引入复杂架构。
3. 回放期间批量加载时序数据，不对 150 艘船逐船、逐帧请求接口。
4. 所有空间查询继续使用绑定参数，禁止拼接 SQL。
5. 页面始终明确显示“教学模拟数据”，不把模拟告警称为真实预测。
6. 每完成一个阶段，更新 README 的“已实现 / 尚未实现”，并形成独立 Git 提交。

### 2.3 当前数据特别适合先做回放

- 每艘船 96 个位置点；
- 每 5 分钟一个位置点；
- 时间范围为 2026-08-30 08:00 至 15:55（`+08:00`）；
- 150 艘船共有 14,400 个位置点；
- 80 个事件的发生时间位于同一时间范围内。

当前规模可以一次加载完整演示时段。未来数据量明显增大后，再改为按时间窗口分段加载。

当前事件还存在一个需要在分析功能前处理的语义问题：80 个事件都位于回放时间范围内，但生成器没有明确区分“与某艘船关联的事件”和“航区级区域事件”。只读核算显示，其中 60 个事件在发生时刻距离至少一艘船不超过 20 公里，另外 20 个不满足该条件。这不代表事件位置一定错误，但说明后续不能默认所有事件都由附近船舶触发。阶段 8 会补充事件范围类型和可验证的关联语义。

## 3. 目标页面与核心交互

桌面端第一版采用简单 CSS Grid，不引入 UI 组件库：

```text

│ 标题 / 模拟数据提示 / 搜索 / 图层 │ 事件目录与详情    │
├──────────────────────────────────┤                 │
│                                  │ 事件筛选         │

│                                  │ 邻近查询结果     │
├──────────────────────────────────┤                 │
│ ⏮  播放/暂停  倍速  当前时间  时间轴 │                 │
```

布局决定：

- 左侧约占可用宽度的 70% 至 75%，右侧事件栏约 360 至 420 像素；
- 时间轴位于地图下方，始终与船位回放处于同一视觉区域；
- 窄屏时右侧栏变为可收起的底部抽屉；
- 地图区域尺寸变化后调用 Leaflet 的 `invalidateSize()`；
- “仅看此船”模式隐藏其他船、事件、港口、右侧栏和普通工具，只保留底图、选中船、轨迹、必要的回放控件和退出按钮。

## 4. 需要先固定的业务语义

### 4.1 时间回放语义

第一版采用离散帧，不先做插值：

- 一个播放帧对应一个 5 分钟采样点；
- `1×` 表示每个现实秒前进一个采样帧；
- 首批提供 `0.5× / 1× / 2× / 4×`；
- 拖动时间轴时立即暂停并跳到目标帧；
- 到达末尾时自动暂停，再次播放时从起点开始；
- 同一时刻直接复用已有 Marker，通过 `setLatLng()` 更新位置，不销毁重建；
- 第二版再增加相邻位置的线性插值，让移动更平滑。

接口统一返回 UTC 时间，前端转换为 `Asia/Shanghai` 展示；所有输入时间必须是带时区的 ISO 8601 字符串。

### 4.2 事件与时间的关系

- 右侧目录保留全部事件，并按发生时间排序；
- 晚于当前回放时间的事件显示为“尚未发生”的弱化样式；
- 地图默认只显示当前时间以前已经发生的事件；
- 提供“显示全部事件”开关，方便教学演示；
- 点击事件目录项后，地图 `flyTo` 到事件坐标，打开 Popup 并高亮对应 Marker；
- 点击地图事件 Marker 后，右侧目录同步选中并滚动到该条目。

### 4.3 轨迹语义

- 普通点击船舶：显示该船信息和轨迹；
- 回放模式下默认高亮“截至当前时间已经航行的部分”；
- 可选显示完整轨迹，未来部分使用较淡的虚线；
- 创建专用 Leaflet Pane，使选中轨迹的层级高于普通 Marker；
- 任意时刻只保留一艘选中船的高亮轨迹；
- 快速切换船舶时，旧请求不得覆盖新选择；
- “仅看此船”可以进入沉浸模式，`Esc` 或退出按钮恢复全部图层和 UI。

### 4.4 右键邻近查询语义

现有 `/ships/{ship_id}/nearby-events` 保持“最新船位 + 纯空间”的既有语义，不破坏兼容性。为回放新增统一的指定时刻上下文查询：

```text
GET /ships/{ship_id}/nearby-context?radius_km=20&at=2026-08-30T10:00:00%2B08:00
```

统一接口应返回：

- 中心船舶及其指定时刻位置；
- 半径内其他船舶、位置时间和距离；
- 半径内已发生事件、发生时间和距离；
- 查询时刻、查询半径和 `is_simulated: true`。

约束：

- 半径必须大于 0，首批按钮为 5、10、20、50 公里；
- 半径设置明确上限，当前模拟海域建议先限制为 200 公里；
- 船位使用 `at` 时刻之前最近一条记录，并排除中心船自身；
- 结果按距离升序；
- 回放历史时刻时不能错误使用最终船位；
- 所有 `:placeholder` 都走绑定参数；
- 前端绘制范围圆，新查询会清理旧圆和旧高亮。

## 5. 渐进式代码结构

不进行一次性大重构。先从 `App.vue` 中逐步拆出真正需要独立维护的部分：

```text
frontend/src/
├── App.vue                       # 页面布局与少量共享状态
├── api.ts                        # API 请求和响应类型
├── components/
│   ├── MapView.vue               # Leaflet 地图、Marker 和图层
│   ├── EventPanel.vue            # 事件目录、详情和邻近结果
│   ├── TimelineControls.vue      # 时间轴、播放、暂停和倍速
│   └── ShipContextMenu.vue       # 右键半径菜单
└── composables/
    └── usePlayback.ts            # 时间推进和帧计算；需要时再创建
```

第一阶段继续由 `App.vue` 持有共享状态，暂不引入 Pinia。建议的最小状态包括：

```text
currentTime
simulationStart / simulationEnd
isPlaying / playbackRate
selectedShipId / selectedEventId
focusMode
shipFilters / eventFilters
nearbyQuery
loadingState / errorState
```

Leaflet 对象统一保存引用：

```text
shipLayer / eventLayer / harbourLayer
selectedTrackLayer / nearbyLayer
shipMarkersById / eventMarkersById
```

这样才能可靠完成时间更新、事件跳转、图层隐藏和旧结果清理。

## 6. 拟新增或增强的后端接口

以下是计划接口，尚未实现：

| 接口 | 作用 | 关键约束 |
| --- | --- | --- |
| `GET /simulation/meta` | 返回起止时间、采样间隔、帧数、场景版本和数据数量 | 从数据库计算时间范围；带 `is_simulated` |
| `GET /ships/playback?start_at=&end_at=` | 批量返回时间段内全部船位 | 参数带时区；限制最大范围和最大点数；按时间、船舶和 ID 排序 |
| `GET /ships/snapshot?at=` | 返回指定时刻每艘船之前最近的位置 | 用于刷新、直接跳时刻和恢复页面状态 |
| `GET /events?start_at=&end_at=&event_type=` | 向现有事件接口增加可选筛选 | 不传参数时保持原行为 |
| `GET /ships/{id}/positions?start_at=&end_at=` | 向单船轨迹增加可选时间范围 | 不传参数时保持原行为 |
| `GET /ships/{id}/nearby-context?radius_km=&at=` | 指定时刻查询附近船舶和事件 | 404、422、空列表语义明确；绑定参数 SQL |
| `GET /events/{id}/nearby-ships?radius_km=` | 从事件反向查看事发时周边船舶 | 可作为后续实用创新点 |

数据库结构变更继续写入编号 SQL。回放阶段预计需要评估并通过 `EXPLAIN` 确认：

- `ship_positions (recorded_at, ship_id, id)` 的全局时间范围索引；
- `events (occurred_at, id)` 的时间筛选索引；
- 现有 `ship_positions (ship_id, recorded_at DESC, id DESC)` 和两个 GiST 空间索引继续保留。

只有查询计划证明需要时才新增索引，不为了“看起来完整”盲目添加。

### 阶段 8：可解释的模拟告警与事件反向关联

优先级：P1，作为实用创新点。

先实现确定性规则，不先接大模型：

- 将事件明确分为“船舶关联事件”和“区域事件”；
- 船舶关联事件根据 `occurred_at` 时刻的真实模拟轨迹点生成；
- 事件增加必要的范围类型、严重程度和场景版本字段；
- 连续低速或停止；
- 短时间内航向明显变化；
- 船舶进入事件影响半径；
- 点击事件后查看“事发时周边船舶”；
- 航线偏离只有在正式定义参考航线和阈值后再实现。

每条告警至少包含：

```text
rule_id / severity / occurred_at
ship_id / event_id
threshold / observed_value / evidence
is_simulated: true
```

验收：

- 固定随机种子产生稳定、可重复的告警；
- 数据生成验收能够验证船舶关联事件的时间和空间关系；
- 每条告警都能说明“为什么触发”；
- 点击告警可定位到对应时刻、船舶和事件；
- 页面不得将规则告警描述成真实预测。

### 阶段 9：自动化测试、性能与安全收尾

优先级：P1，应贯穿前述阶段并在此集中补齐。

任务：

- FastAPI 测试覆盖时间范围、回放、附近查询和错误分支；
- 前端测试覆盖帧计算、倍速、筛选、快速切船和事件联动；
- 数据库按编号 SQL 增加必要的经纬度、速度和航向检查约束；
- 浏览器回归覆盖五项核心交互；
- Popup 不再直接信任外部字符串，使用 `textContent` 或可靠净化；
- 请求支持取消，卸载时清理计时器和监听器；
- 以 150 艘船、14,400 个位置、80 个事件完成性能验收；
- 增加统一的用户可见错误和重试入口。

验收：

- 前后端核心测试通过；
- `npm run build` 通过；
- 浏览器控制台和网络面板无未处理错误；
- 外部地图或港口服务失败时，核心模拟态势仍可使用。

### 阶段 10：面向大模型与智能体的准备层

> 2026-09-14 更新：当前先做“大模型 API + 自定义只读查询工具”的最小通行问答，不引入 LangChain/LangGraph。以 [智能体接入契约](agent_integration.md) 为准；下列地图上下文、工具和动作保留为后续规划。

优先级：P2，在确定性查询和告警稳定后实施。

先定义只读、可追溯的上下文对象：

```text
MapContextSnapshot
├── current_time / time_range / map_bounds
├── selected_ship / selected_event
├── nearby_ships / nearby_events
├── active_filters
├── alerts_with_evidence
└── is_simulated / data_timestamp
```

推荐的智能体只读工具：

- `search_ships`：按字段查找船舶；
- `get_ship_track`：查询指定时间范围轨迹；
- `get_nearby_context`：查询指定时刻邻近关系；
- `get_event_context`：查询事件和事发时周边船舶；
- `get_situation_snapshot`：获得当前地图范围的结构化摘要。

可逐步实现的能力：

1. 解释一条模拟告警；
2. 生成当前时刻的态势摘要；
3. 比较两个时刻的态势变化；
4. 将自然语言意图转换为白名单地图动作，例如 `focus_ship`、`focus_event`、`set_time`；
5. 保存一个带时间、筛选和选中对象的教学演示书签。

安全边界：

- 模型不得直接连接数据库或执行任意 SQL；
- 模型密钥只保存在后端环境变量中；
- 模型输出必须带船舶 ID、事件 ID、时间、距离或规则证据；
- 前端只执行经过校验的白名单动作；
- 模型不可用时，地图、回放、筛选和规则告警仍能独立运行。

## 10. 主要风险与控制办法

| 风险 | 控制办法 |
| --- | --- |
| `App.vue` 继续膨胀 | 按真实交互边界渐进拆分四个组件，不一次性重构 |
| 时间播放产生大量请求 | 使用批量时间范围接口，一次加载当前演示时段 |
| 每帧重建 Marker 导致卡顿 | 保存 Marker 引用，只调用 `setLatLng()` |
| 快速切船显示错误轨迹 | 使用 `AbortController` 或请求序号，忽略过期响应 |
| 轨迹被图标遮挡 | 为选中轨迹建立高于 Marker 的专用 Pane |
| 历史邻近查询误用最终船位 | 新接口必须接收 `at` 并使用该时刻之前最近船位 |
| 时间和时区混乱 | API 统一返回 UTC，UI 转换并明确显示北京时间 |
| 区域事件被误当成船舶事件 | 增加事件范围类型，船舶关联事件按发生时刻轨迹生成并验收 |
| 外部文本造成 HTML 注入 | Popup 使用 DOM `textContent` 或可靠净化 |
| 模拟结果被误认为真实态势 | 页面、接口和报告持续返回并显示模拟数据标识 |
| 过早引入复杂技术 | 每项新依赖必须由实际性能或功能问题证明必要性 |

## 11. 当前阶段不应过早实施

- 不接入未经核验的真实 AIS 或新闻数据；
- 不把当前系统称为实时态势系统；
- 不引入 Redis、消息队列、微服务或复杂缓存；
- 不因“已安装”就改造为 TimescaleDB 或 MobilityDB 业务模型；
- 不提前引入 Pinia、大型组件库、图表库或 Marker 聚合插件；
- 不允许大模型直接执行 SQL；
- 不在缺乏参考航线和阈值时声称已实现航线异常识别；
- 不在当前核心交互未完成时优先开发登录、权限和正式部署。
