## 功能定位

「动态海峡观测通行统计」：按选定历史条件查询已入库 `nnu_ais` AIS（不是实时接入），
用户既可以在地图工具栏「通行」打开的面板手动选择条件查询与比较，也可以让智能体调用
相同能力。两种入口复用同一统计服务、筛选条件和判定口径，同条件结果一致。

- 单时段：起止日期（UTC 自然日，结束日含在区间内；后端为带时区半开区间
  `[start_at, end_at)`）、船型多选（含「未知/缺失」桶）、方向（全部/入湾=东→西/出湾=西→东）。
- 多日：单时段最长 7 天；按日统计（确定通行次数、去重艘数、入湾/出湾次数、不确定候选数量）
  与全窗汇总。
- A/B 比较：两期共享船型与方向筛选；允许不等长窗口；返回两期指标、差值、`(B-A)/A` 变化率
  （A=0 时为 `null`，绝不生成 Infinity/NaN）、窗口长度、日均次数与覆盖可比性说明。

## 判定口径（与 `strait_passages.py` 完全一致）

- 虚拟双门线：纬度 25.8–27.1°N 内 56.2°E 西侧与 56.7°E 东侧；仅经度 55.8–57.1°E、
  来源 `nnu_ais` 的报位参与判定；完成侧首个报位时间 ∈ 窗口记一次观测通行。
- 服务端逐日编排：UTC 自然日子窗 ≤24h，每窗保留 24h 前置侧别回看；跨日通行由完成观测
  时间归入唯一一天。等效性：每窗判定即已验证的单窗算法，全窗结果 = 各窗结果按
  稳定证据键去重后的并集（不是各窗数字的简单相加：全窗去重艘数 ≠ 每日去重艘数之和）。
- 稳定证据键 `ship_id:起始报位id:完成报位id`（源行 id，跨调用/分窗稳定）；
  不依赖每次调用重置的 P1/P2 编号；同秒冲突由 id 区分，不静默去重。
- 不确定候选（中间报位离开走廊 / 间隔 >6h / 推算航速 >30kn）单列，不计入确定量；
  保留原因。归日时间为观测完成时间，不是精确越线时刻。
- 船型分类来自 `ships.ship_type` 原始字段（当前快照），不按船名推断；
  「未知/缺失」桶 = NULL 或原始标签「未知」，与全部船型查询口径一致地在 SQL 候选计算前过滤。
- 无报位/不足判断 ≠ 真实零通行；接口故障、超限、超时不得回填为零；每日状态区分
  `ok` / `zero`（有观测无确定通行）/ `partial`（含候选）/ `no_observation`。
- 七日全船批次（`source_batch_id` 1–7）与独立单船案例补充（批次 8）在元数据与限制中区分；
  案例补充不是海峡全量覆盖。统计附带来源批次、范围、判定版本（`determination_version`）
  与限制说明；查询只读，不触发导入、迁移或派生重建，不开放任意底表 SQL。

## 接口（手动面板）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/strait-passages/meta` | 船型选项（含未知/缺失桶与船数）、按批次的来源覆盖、判定参数与版本；不硬编码历史数量 |
| POST | `/api/strait-passages/statistics` | `{start_at, end_at, ship_types?, direction?}` → 按日统计 + 全窗汇总 |
| POST | `/api/strait-passages/compare` | `{a_start_at, a_end_at, b_start_at, b_end_at, ship_types?, direction?}` → 两期比较 |
| GET | `/api/strait-passages/evidence` | `start_at/end_at` + 可选 `day`/`ship_types`/`direction`/`include_uncertain`/`page`/`page_size`（≤200）→ 证据分页；`matched_count`/`confirmed_count` 为完整统计，不受分页影响 |

错误统一为 `detail{code, message, request_id}`；参数非法 422，数据库故障 500，不截断、
超限明确拒绝。

## 智能体工具（与面板同一服务）

- `query_strait_passage_statistics(start_at?, end_at?, ship_types?, direction?)`：一次调用完成
  服务端多日编排；只向模型返回有界统计摘要（每日计数 + 全窗汇总 + 限制），不含证据明细、
  全量轨迹，模型不得自行数明细或算百分比。时间省略时退化为请求窗口。
- `compare_strait_passage_statistics(a_start_at, a_end_at, b_start_at, b_end_at, ship_types?, direction?)`：
  两期必须显式给带时区的起止时间；参数歧义时模型应澄清，后端校验不依赖模型遵守描述。
- 响应新增 `analysis_actions`（v4 增量）：由成功的统计/比较工具结果生成
  `{type: "passage_analysis", trigger: "suggested", query, summary}`，**绑定该次调用自己的
  查询参数**；前端「查看通行分析」按钮据此打开地图右侧通行面板并恢复条件与结果，用户可继续手动
  调整；历史回答的动作不会误用当前最新结果。
- 原 `query_strait_passages` 单船证据能力保持不变（共享同一 SQL 核心）。

## 前端

- 入口：地图工具栏「通行」，展开右侧停靠面板（`PassageAnalysisPanel.vue`）；新闻栏平滑收起，可通过边缘三角重新展开。2026-10-25 新布局已随 PR #66 合入 main，原总览入口属于迁移前版本。
- 固定历史油轮通行序列（`domain/tankerPassages.ts`）仍作为历史独立复核对照展示，
  已标注「固定批次、非动态查询结果」，不再充当动态结果。
- 面板：单时段/比较模式、UTC 日期选择（结束日包含关系有说明）、船型多选（默认全选，
  含未知/缺失）、方向筛选、按日柱状图（比较模式按各自第 N 天对齐并保留实际日期，
  不误导为同时发生）、汇总卡片、比较表（差值/变化率/窗口长度/日均/可比性说明）、
  证据明细分页（船舶标识、方向、两端报位时间/位置、观测完成时间）。
- 地图联动：证据行「查看轨迹」复用智能体地图动作执行器，显示完成观测时间 ±6h（裁剪到
  查询窗口）的该船轨迹，并标明证据时段与回放时段；不把当前快照位置充当通行位置。
- 状态：加载/取消（AbortController + 请求序号，旧响应不覆盖新条件）、错误、无观测、
  有效零结果、部分覆盖均有区分提示；条件修改后旧统计标注「结果对应上次查询」。
