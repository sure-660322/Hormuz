## 界面与时间规则

- 顶部“典型案例”入口并列于态势总览/地图探索；左侧固定三阶段横向导航，下方一个详情区，右侧复用地图，顶部复用项目现有时间轴。概况展示全部六篇报道；3月31日官方回应作为后续资料，不作为第四个航行按钮。
- 三个航行阶段：3月27日首次尝试、3月28—29日等待、3月30日再次通过。窗口按北京时间日期划分，数据库和接口使用带时区 UTC；它们不是自动识别的事件时刻。API保留confirmation资料节点供概况引用，未删除后续证据。
- 进入即加载3月27—31日完整单船范围，初始停在案例末帧且不自动播放。完整轨迹一次以五个 ≤24 小时请求获取、按报位ID去重并重新断开 >90 分钟空缺；阶段切换只定位时间与视野，不重新加载轨迹或缩短时间轴。
- 淡线显示完整观测轨迹（含当前帧之后的历史观测，供整体对照）；亮线显示当前阶段截至回放时刻的部分，概况亮线从案例起点开始。背景不表示当时已航行路线，不跨缺口插值。报位点默认关闭，面板可显式开启。
- 报道采用左图右标题：四篇使用2026-09-30原文核对的正文配图或页面封面（image_kind、image_source_url记录来源）；两篇无合适原图用占位图，外链图片加载失败同样回退。图片直接引用原站，不下载提交或据配图推定船舶身份；页面仅展示“原文配图”。
- 快照只采用此前1小时内最新报位；缺报显示“无有效报位”，不表示船舶不存在。不跨缺口插值。
- 案例快照仅保留目标船；不绘制未绑定的全局新闻点。相关报道在阶段面板阅读。原地图/新闻时间门控仍用于普通态势。
- 收起案例面板仍保留案例地图，可重新展开；退出或切换回普通导航后，恢复进入前的回放时刻、视野、船/事件选择、详情面板、图层与列表状态。
- 默认 `/simulation/meta` 排除 `ais_import_batches.source_file LIKE 'case/%'` 的补充报位；原七日默认范围不被延伸至3月底。真实轨迹工具与只读语义视图继续使用 `nnu_ais`，可按明确窗口查询案例数据。
- 案例内提问携带目标船 ID 与地图回放时刻；缺省查询窗口为选中阶段内、当前时刻前最多24小时；若当前帧早于选中阶段则以阶段末时刻为界，概况则使用案例范围内当前时刻前最多24小时。显式问题/高级设置优先，越出阶段提示返回概况或选择对应阶段，改查其他船需退出案例，不静默改变范围。切换阶段取消过期请求，普通地图刷新不取消。

### 复现命令

从配置好后端运行环境的仓库根执行，先只读审计：

```powershell
python -m backend.import_case_ais <本机CSV绝对路径> --report local-archive/arctic-ocean-audit.json
```

写入前检查目标和备份，先使用独立测试库；显式 `--apply --database <目标库>` 才追加。数据库需已有014对应批次表、字段、约束和生成列；此脚本不执行迁移或建库。文件哈希幂等检查，同船窗口重叠/IMO冲突拒绝，参数化SQL，失败整体回滚。不得把带隔离行的案例文件交给七日按日导入脚本；两者批次预期行数规则不同。

```powershell
python -m backend.import_case_ais <本机CSV绝对路径> --report local-archive/arctic-ocean-import.json --apply --database <目标库>
```

`expected_rows` 记录原始数，`inserted_rows` 记录接受数；差额由原文件和审计报告解释。数据库包含原始行号、批次哈希、Unix秒和保留的目的地/ETA/来源字段；不新增未经核验的 MobilityDB 派生层。数据库内容不会随 PR 自动共享，其他环境未导入时案例显示“轨迹尚未导入”，仍可阅读报道。
