# 旧事件功能适配：可行性研究与验证

验证日期：2026-09-09。结论依据当前数据库、工作区代码、实际HTTP请求和只读原型，不以历史说明代替当前事实。

## 结论

可以在现有表结构上完成适配，当前规模无需新增依赖或先建设复杂架构。推荐先恢复新闻事件独立浏览，再适配地图和来源展示；模拟船舶回放维持独立时间范围。

不能仅靠字段重命名恢复完整功能：新事件可无时间、无坐标、有多个地点和多篇报道，且与船位时间不重合。当前数据不支持“事件发生时附近有哪些船”“哪些船受事件影响”等实际关联判断。

本轮未修改业务代码、路由、数据库结构或数据；仅新增本报告、独立只读验证脚本及结果文件。运行构建与原有检查产生了常规忽略目录下的输出。

### 数据边界

- 65个事件，290条新闻，其中223条有事件外键、67条无关联。
- 40个事件有代表点，25个没有；27个有 event_datetime，38个没有；时间和坐标同时存在的只有23个。
- 16个事件有非空多点数组，共57个点，坐标数值及范围校验通过。代表点与多点不能相加当成事件数量。
- 地理编码来源：22个 nominatim、7个 region_centroid、11个 multi、25个字符串 `null`。地名检索点、区域中心和多点代表位置均不等同于精确事发坐标。
- 新闻发布日期范围为2026-02-26至2026-03-02；已填事件时间范围为2026-02-26至2026-03-05。
- `evt_049` 的时间文字为“3月2日报道，3月5日伦敦午夜生效”。因此不能把报道截止日当作事件时间上限；当前UTC存储不能替代原始文字的时间精度与语义。
- 船位范围为2026-08-30 00:00—07:55 UTC，96帧。所有已填事件时间都不在这一范围。
- 新闻全部无坐标；14个事件有船名数组，但与 ships 的不区分大小写同名匹配数为0。这仅是字符串匹配核验，不能用名称推定船舶身份；本轮未处理 vessels_mapping。

## 2. 运行原型证明了什么

独立脚本 `scripts/verify_event_adaptation.py` 在 `SET TRANSACTION READ ONLY` 下运行，数据库禁止该事务写入。输出见 `docs/event_adaptation_verification.json`。

1. **候选新响应结构可行**：65个事件全部通过允许空时间、空坐标及多点的核心响应模型；关联223条新闻，每个事件的新闻数量与 coverage_count 完全一致。候选核心字段和全部关联新闻摘要序列化约168 KB。这是原型，不是已上线API；生产列表可只返回摘要，详情再按需取新闻。
2. **简单改名不可行**：把 title_zh→title、summary_zh→description、event_lat/lng→latitude/longitude、event_datetime→occurred_at，并让旧单一来源为空后，旧 EventResponse 只有23条通过，42条失败。
3. **不加空间列也能查询**：用现有代表点临时构造 geography，执行 ST_DWithin/ST_Distance，150艘船最新位置与事件的20公里比较得到72组结果，一次本机查询约50 ms。EXPLAIN实际执行计划已保存；这不是并发/扩容性能保证，也不是同一时间的船舶事件关系。
4. **前端语义问题可复现**：运行现有检查编译出的实际函数，attack/blockade/passage/market/analysis/other 全部落为“其他事件”和 normal；空坐标调用 toFixed 抛 TypeError；空坐标在距离公式中可能被当成0；2—3月事件 seek 到8月第一帧，null 时间 seek 到末帧。

验证命令（项目根目录）：

```powershell
cd D:\my_project\Hormuz
.\backend\.venv\Scripts\python.exe -m scripts.verify_event_adaptation
```

## 3. 功能影响与建议

| 功能 | 现有依赖 | 建议适配 | 可行性 |
| --- | --- | --- | --- |
| 事件列表/搜索 | 旧字段、强制时间 | 使用中文标题摘要；容纳全部65条；无时间显示原始文字或“时间未明确” | 高 |
| 分类 | conflict等旧枚举 | 改为attack/blockade/passage/market/analysis/other，提供中文标签 | 高；不要顺带推断风险等级 |
| 时间排序 | Date.parse(occurred_at) | 明确按报道日期排序；发生时间为空单独处理，不把发布日期伪装成发生时间 | 高 |
| 事件详情/来源 | source_name/source_url | 展示coverage_count、视角、逐篇新闻标题、媒体、日期、canonical_url | 高 |
| 地图事件 | 每条都有坐标；仅已发生可显示 | 先绘制40个代表点；无坐标事件保留列表，禁用定位；说明代表点性质 | 高 |
| 多点事件 | 一事件一Marker | 第二步选中事件后显示event_points，按event_id聚合计数；使用地点名和方法说明 | 高，但增加交互范围 |
| 点击事件 | 同时定位和seek | 浏览详情；有坐标才定位；本批新闻不驱动模拟船舶时间轴 | 必须调整 |
| 船舶回放时间轴 | 用船位帧画事件刻度 | 保持船位范围；移除本批新闻在模拟回放上的“已发生/待回放”和告警含义 | 必须调整 |
| 船舶附近事件API | events.location与旧列 | 临时构造代表点进行纯地理比较；返回数据来源和时间不重合说明；不表示事件关联 | 技术可行，默认UI建议暂不展示混合关系 |
| 前端附近事件/连线/区域查询 | 本地distanceNm与船位回放时刻 | 必须同时改本地计算；只修后端不会改变这条前端路径；初期关闭新闻与模拟船位连线 | 必须调整 |
| 模拟元数据 | count所有events + is_simulated=true | event_count只表达模拟回放事件（当前为0），新闻数量由事件响应提供；保留船位回放字段 | 小改即可 |
| 船舶“新闻”标签 | 未接入占位 | 事件详情先接新闻；船舶新闻仍不能按船名数组强行关联 | 暂缓船舶关联 |
| 分享、打印 | 数字id、旧坐标/时间、全模拟文案 | 空值防护、区分船位和新闻来源；新分享链接宜用业务event_id，避免重导后数字id指向变化 | 随主适配检查 |

## 4. 现有数据库是否需要再改

**第一阶段不需要。** 现有唯一约束、新闻外键和JSONB足以完成基本浏览。

- news.event_id没有索引。290条新闻阶段可顺序扫描；规模扩大或详情查询变慢再按实测增加普通索引。
- events没有location/GiST。65条事件可用已验证的表达式查询。若将来增加生成列，应通过新的编号SQL维护，且只对有效坐标生成；不能让应用手写空间字段。
- 不要把多点中心、区域中心直接用于精确附近事件判断。需要正式多点空间分析时再确定“最近地点、代表点、区域范围”各自语义，避免直接建复杂表。
- 时间精度未独立存储，不能可靠区分真实午夜与日期占位零点。初期优先原始时间文字并避免时刻级播放；后续如要事件时间轴，再补充精度字段和逐条核验规则。
- 图片路径相对 `D:\my_project\news_raw_data`，不是浏览器URL。初期展示新闻链接即可，图片服务作为独立小步骤，不能直接暴露任意本地路径。
- 无关的67条新闻仍保留数据库，不应出现在任一事件详情；若需要独立新闻列表，再单独增加入口。

适配事件类型、列表/详情/搜索、空值、40个地图代表点及来源文案；解除事件选择与模拟seek；停止混合船位连线、新闻“已发生”统计和模拟告警提示。保持现有页面布局和船舶回放。
