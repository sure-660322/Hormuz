## 前端阶段一：历史船位快照

阶段一历史验收：2026-09-25 **在独立试点库已实现并浏览器验证**。`GET /ships/snapshot?at=<带时区时间>` 以 `(ship_id, recorded_at DESC, id DESC)` 索引按船查所选时刻前 1 小时内最近报位，每船最多返回一条；`south/north/west/east` 四个边界参数可选，但必须完整且有序。过期报位不伪装为当前船位。前端真实 AIS 模式当时只保留当前快照，不调用全日 `/ships/playback`；连续播放随后由阶段二接入，单船轨迹仍未接入。新闻和派生层只在目标库存在对应表时加载。

## 前端阶段二：有界窗口连续回放

状态：2026-09-25 **在独立试点库已实现并浏览器验证**。`GET /ships/snapshot-window?at=<ISO时间>&at=...` 接受 1–4 个严格递增、均带时区的快照时刻，总跨度不超过 15 分钟；单帧最多 5,000 艘，整个响应最多 20,000 艘次。每帧沿用“截至该时刻、此前 1 小时内每船最近报位”的规则，结果包含帧时刻、船舶数组和 `max_age_seconds=3600`。无时区、重复时刻、超过帧数或跨度时返回 422。查询按船使用现有复合索引；不扫描后将全天报位传给浏览器。

前端按 5 分钟刻度播放、暂停和拖动；一次窗口最多缓存 4 帧，总缓存最多 12 帧。接近缓存末端时预取后续窗口；目标帧未到时暂停推进，地图、船舶详情和地图上的快照时间保留上一张已完成帧，同时显示正在请求的目标时刻。远距离拖动取消过期窗口请求，只允许最后选择的帧提交显示。播放速率是目标上限，实际推进受查询与绘图耗时限制。原模拟数据回放路径未改；真实 AIS 的单船轨迹仍未接入。

验证证据：试点库 `TestClient` 查询 UTC 15:40、15:45、15:50、15:55 四帧返回 200，分别为 1,789 / 1,782 / 1,773 / 1,767 艘，单次本机耗时约 0.24 秒；缺时区、5 帧请求均返回 422。Playwright 5176/8002 页面从日末点击播放后自动回到起点，持续推进到第 46/289 帧，网络仅出现 4 帧一窗的 `/ships/snapshot-window` 请求，没有全日 `/ships/playback`；暂停后拖到 UTC+8 12:00，地图快照更新为 1,790 艘，浏览器会话控制台 0 error。`frontend/checks/workbench.cjs` 另覆盖目标帧加载期间旧快照保留和缓存命中直接切换；`npm run build`、`npm run check:workbench`、后端 `pytest backend/tests -q` 均通过。以上是本机单日单浏览器验证，不是整周或并发吞吐证明。

按 MMSI 分组重新顺序扫描该日 CSV，同一船出现不同非空元数据的船数：`ShipName` 89、`ShipTypeCN` 40、`IMO` 8、`CallSign` 20、`Length` 52、`Width` 40、`Dwt` 26。当前 `ships` 是最新报位的属性快照，历史变化仍在原始 CSV，不能把快照反推为所有时刻的身份属性。
另一次扫描确认：最新报位属性为空、但同船较早报位有非空值的情况，在上述七个字段均为 0；本日快照未因“最新一条为空”遗漏可用值。这一结论只针对本文件。

## 前端阶段三：按需单船轨迹

状态：2026-09-25 **在独立试点库完成接口与浏览器验证**。选中船并点击“查看轨迹”后，`GET /ships/{ship_id}/track-window?from=&to=&bucket_seconds=` 只按船和时间窗查询既有 `(ship_id, recorded_at)` 索引；必须使用带时区的起止时间，窗口不超过 24 小时。单窗最多读取 10 万条原始报位、最多返回 5,000 个采样点；超过限制返回 422。前端提供最近 1 / 6 / 24 小时范围，对应 30 / 120 / 300 秒时间桶，只保留当前选中船的请求，切换船、时间或范围时取消旧请求。服务端按真实相邻报位间隔超过 90 分钟分段，抽稀时保留每段首尾；地图逐段绘制，不跨断档连线。面板显示原始报位数、实际采样点数、段数及断档最长时长。这里的点是桶内首条实测报位，没有插值，也没有重建 MobilityDB `ship_tracks`。

本机接口实测：最多报位的 `ship_id=1863` 在 24 小时窗口返回原始 25,823 条、5 分钟桶 289 点、1 段；30 秒桶返回 2,597 点。该船全窗 `EXPLAIN (ANALYZE, BUFFERS)` 使用 `idx_ship_positions_ship_recorded_at`，SQL 执行约 11 ms、排序内存约 2.6 MB（单次本机测量）。`ship_id=9` 的 3 条报位返回 2 段、1 处约 337.4 分钟断档；其空窗口返回 0 点、0 段，未知船返回 404，缺时区返回 422。`/health`、`/docs` 均为 200。Playwright 在 5176/8002 页面选中 ACACIA 后，24 小时窗口显示原始 1,950 条、采样 274 点；切换至 1 小时后为原始 42 条、采样 35 点，控制台 0 error。后端 `pytest backend/tests -q` 为 246 passed、12 skipped，前端 `npm run build` 与 `npm run check:workbench` 通过，`git diff --check` 通过。以上为本机单船、单日验证，未覆盖多用户并发或整周连续轨迹；断档阈值仅用于绘图，不等于船舶停航。旧模拟模式仍沿用原有轨迹和派生速度着色路径。

2026-09-25 阶段三补充：真实 AIS 船舶详情恢复“速度着色”，另加“显示报位点”开关。着色按每条采样线段**起点实测 SOG**进入既有四档色带，不调用模拟批次的 MobilityDB 插值速度；颜色表示起点样本，不能解释为两次报位之间每一刻的实际航速。报位点开关默认关闭，开启后仅绘制接口返回的抽稀采样点（最多 5,000），悬停显示该点时间、经纬度、SOG；单点轨迹段始终可见。两项开关只改变地图绘制，不增加数据库查询，也不跨报位断档连线。Playwright 在 5176/8002 选中 GAS ARIES：24 小时窗原始 4,700 条、采样 179 点、2 段、断档 161.8 分钟；分别验证着色开关与采样点开关的地图效果，控制台 0 error。本轮 `npm run build`、`npm run check:workbench` 通过；真实 AIS 的航速曲线仍未接入。
